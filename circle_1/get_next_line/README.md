# get_next_line

## Description

`get_next_line` は、**ファイルディスクリプタから1行ずつテキストを読み取る**関数を実装するプロジェクトです。

呼び出すたびに、そのファイルディスクリプタが指すテキストを1行ずつ返します。C の標準ライブラリには `getline()` がありますが、本プロジェクトではそれを `read()` / `malloc()` / `free()` の3つだけで自作します。目的は、**`static` 変数・動的メモリ管理・ファイル I/O** の仕組みを自分の手で理解することにあります。

**プロトタイプ**

```c
char	*get_next_line(int fd);
```

**仕様**

- 呼び出すたびに、ファイルディスクリプタ `fd` から次の1行を返す
- 返す行には改行文字 `\n` を含む（ファイル末尾が改行で終わらない最終行を除く）
- 読み取るものが無くなった場合、またはエラーが発生した場合は `NULL` を返す
- 通常ファイルと標準入力の両方で動作する
- `BUFFER_SIZE` の値（`1`, `42`, `9999`, `10000000` など）に関わらず同じ結果を返す
- 呼び出し側は、返された行を `free()` する責任を持つ

**制約（subject より）**

- 使用可能な外部関数は `read`, `malloc`, `free` のみ
- `libft` の使用は禁止
- `lseek()` の使用は禁止
- グローバル変数の使用は禁止
- 42 の Norm に準拠すること

> **スコープ:** 本実装は mandatory part を対象としています。`static` 変数は1つですが、複数の fd を同時に扱う bonus part には対応していません。

### コンパイル

`BUFFER_SIZE` はコンパイル時に `-D` フラグで指定します。

```sh
cc -Wall -Wextra -Werror -D BUFFER_SIZE=42 get_next_line.c get_next_line_utils.c
```

`-D BUFFER_SIZE` を付けずにコンパイルすることもできます。その場合はヘッダ内の

```c
# ifndef BUFFER_SIZE
#  define BUFFER_SIZE 42
# endif
```

により既定値 `42` が使われます（`-D` を付けた場合はコマンドラインの値が優先されます）。既定値 `42` に特別な意味はなく、subject も任意の値でよいとしています。

### 区切り文字を変える

行の区切り文字も同じ仕組みでコンパイル時に差し替えられます。既定は `'\n'` です。

```sh
cc -Wall -Wextra -Werror -D BUFFER_SIZE=42 -D "LINE_DELIMITER='A'" \
   get_next_line.c get_next_line_utils.c
```

`fooAbarAbaz` を読ませると `"fooA"` → `"barA"` → `"baz"` の順に返ります（区切り文字を含み、最後の区切り無しの断片も返る点は `'\n'` のときと同じ）。`-D` を付けなければ従来どおり `'\n'` 区切りなので、mandatory part の挙動は一切変わりません。

`test.c` はカレントディレクトリの `test.txt` を1行ずつ読んで表示します。実行前に `test.txt` を用意してください。

```sh
printf 'hello\nworld\nno newline at eof' > test.txt
```

`BUFFER_SIZE` を `1` や `9999` に変えて再ビルドし、出力が変わらないことを確認できます。

## Algorithm

行を返すには、「改行が現れるまで読み進め、余った分を次回の呼び出しのために保持する」必要があります。この**持ち越し分**を保持するのが `get_next_line()` 内の `static t_save s` です。`static` なので関数を抜けても値が保持され、次の呼び出しで続きから処理できます。

### 状態の持ち方

持ち越し分は「`\0` 終端の文字列」ではなく、**バイト列 + 有効長 + 確保済み容量**の3つ組で保持します。

```c
typedef struct s_save
{
	char	*data;	/* 持ち越しバイト列 */
	size_t	off;	/* 有効データの開始位置 */
	size_t	len;	/* 有効バイト数 */
	size_t	cap;	/* 確保済みバイト数 */
}	t_save;
```

この形にした理由は4つあります。

1. **長さを毎回数え直さなくてよい** — 文字列として持つと、連結のたびに先頭から `\0` を探して長さを求める必要があります。`len` を持てばその走査は不要です。
2. **`\0` を含むデータでも壊れない** — subject はバイナリファイルを未定義動作としていますが、途中に `\0` が現れても行の切れ目（区切り文字）を見失いません。
3. **容量 `cap` を分離できる** — 「必要なバイト数」と「確保済みのバイト数」を別々に持てるため、後述の**容量の使い回し**が可能になります。
4. **開始位置 `off` を分離できる** — 行を返したあと、残りをバッファ先頭へコピーし直す必要がなくなります。これが `BUFFER_SIZE` が大きいときの性能を決めます（後述）。

`static` 変数はこの構造体1つだけで、グローバル変数は使っていません。

### 全体の流れ（`get_next_line`）

1. `fd < 0` または `BUFFER_SIZE <= 0` なら `NULL` を返す（引数の検証）。
2. `fill_save()` — 持ち越し分の中に `\n` が現れるか、EOF に達するまで `read()` を繰り返し、読んだ内容をバッファ末尾に追記する。**すでに `\n` を持ち越していれば `read()` を1回も呼ばない。**
3. 読むものが無くなった（`len == 0`）／エラーが起きた場合は、`reset_save()` でバッファを解放して `NULL` を返す。
4. `str_line()` — バッファ先頭から最初の `\n` まで（`\n` を含む）を `\0` 終端でコピーし、返す行を作る。`\n` が無ければ末尾まで（＝最終行）。
5. `consume()` — 返した分だけ開始位置 `off` を進め、`len` を減らす。**ここでは `malloc` も `free` もコピーもしない（O(1)）。**
6. 切り出した行を返す。

```
呼び出し1: [ 読み込み ] a b c \n d e        → "abc\n" を返す
                                    ↓ consume（off を進めるだけ）
持ち越し:  a b c \n d e
                   ↑ off = 4、len = 2（コピーは発生しない）
呼び出し2: 持ち越しに \n が無い → read() を継続 …
```

### 各関数の役割

| 関数 | ファイル | 役割 |
| --- | --- | --- |
| `get_next_line(fd)` | `.c` | 入口。検証 → 充填 → 切り出し → 前詰め、の流れを組み立てる |
| `fill_save(fd, s)` | `.c` | 開始時点で `\n` があれば即座に成功を返す。無ければ `BUFFER_SIZE` 分ずつ `read()` → `append()` を繰り返し、`\n` が見つかるか `read()` が `0` を返した時点で抜ける。`read()` が `-1` を返したら失敗を返す |
| `append(s, buf, n)` | `.c` | 必要なら `compact()` で先頭に寄せ、`grow()` で容量を確保してから、読み込んだ `n` バイトをバッファ末尾にコピーし `len` を進める |
| `compact(s)` | `.c` | `off` がずれているときだけ、有効データをバッファ先頭へ寄せて `off` を 0 に戻す |
| `grow(s, need)` | `.c` | `need` バイト入るまで容量を**2倍ずつ**拡張する。容量が足りていれば何もしない（`malloc` しない）。初期容量は `BUFFER_SIZE + 1` で、`read()` 1回分が必ず収まる |
| `nl_pos(s, from)` | `utils.c` | `from` 以降で最初の区切り文字の位置を返す（無ければ `-1`）。追記直後は**新しく読んだ範囲の先頭**を `from` に渡すため、走査が重複しない。**実装中で区切り文字を比較しているのはこの1か所だけ** |
| `str_line(s, &len)` | `utils.c` | 先頭から最初の区切り文字（を含む）までを `\0` 終端でコピーして返す。切り出した長さを `len` に書き戻す |
| `consume(s, len)` | `utils.c` | 開始位置 `off` を `len` だけ進め、`len` を減らす。**コピーは発生しない（O(1)）** |
| `reset_save(s)` | `utils.c` | バッファを解放し、`data`/`off`/`len`/`cap` をゼロに戻す |

### なぜこの設計にしたか（justification）

#### 1行ぶんだけ読む

`fill_save()` は `\n` を見つけた時点で読み込みを止めるため、ファイル全体を一度に読み込むことはありません。さらに、前回の呼び出しで持ち越したデータの中にすでに `\n` があれば `read()` を1回も呼びません。これは subject が明示する「新しい行を見つけたらその行を返せ／ファイル全体を読んでから処理するな」という要件をそのまま満たします。

#### `BUFFER_SIZE` から独立させる

読み込み単位（`BUFFER_SIZE`）と行長を完全に分離し、その差を追記ロジック（`grow` + `append`）が吸収します。そのため `BUFFER_SIZE` が `1` でも `9999` でも出力は同一になります（[検証](#検証)を参照）。

#### 容量を2倍ずつ広げる（償却計算量）

「読むたびに持ち越し全体を新しく `malloc` してコピーし直す」素朴な実装では、長さ `N` の行を `BUFFER_SIZE` ずつ読む間に `O(N / BUFFER_SIZE)` 回の `malloc` と、合計 `O(N² / BUFFER_SIZE)` バイトのコピーが発生します。行が長く `BUFFER_SIZE` が小さいほど爆発的に遅くなります。

そこで `cap` を持ち、**足りないときだけ容量を2倍にする**方式にしました。拡張は `log₂(N)` 回しか起きず、コピーの総量は等比級数で抑えられて `O(N)` に収まります。

実測（`'x' × 20000` + `\n` + `y\n` の 20003 バイトを読み切るまでに `get_next_line` 内部で呼ばれた `malloc` の回数。返す行の確保と一時読み込みバッファを含む）:

| `BUFFER_SIZE` | 毎回連結し直す素朴な実装 | 本実装 |
| --- | --- | --- |
| `1` | 20005 回 | **20 回** |
| `10` | 2004 回 | **16 回** |
| `42` | 480 回 | **14 回** |
| `9999` | 6 回 | **7 回** |
| `10000000` | SIGSEGV でクラッシュ | **5 回** |

`BUFFER_SIZE` を小さくしても本実装の確保回数はほとんど増えません。素朴な実装が `BUFFER_SIZE` に反比例して増えるのとは対照的です。読み取り単位が行長を上回る `9999` 以降はどちらも `read` 1回で済むため差は消えます。

#### 一時バッファをヒープに取る

`fill_save()` の読み込み用バッファは `char buf[BUFFER_SIZE];` ではなく `malloc(BUFFER_SIZE)` で確保しています。スタックに取ると `BUFFER_SIZE` が大きいときに**スタックオーバーフローで即クラッシュ**するためです（macOS の既定スタックは 8MB なので `10000000` で落ちます。上の表で素朴な実装が SIGSEGV しているのはこれが原因です）。ヒープであれば失敗しても `malloc` が `NULL` を返すだけなので、`NULL` を返して安全に終われます。

#### 持ち越しは再確保もコピーもしない

行を返したあとの残りは、新しくメモリを確保し直すことも、バッファ先頭へ詰め直すこともしません。**開始位置 `off` を進めるだけ**です（`consume()`）。次の行を読むときも同じバッファをそのまま使い回せるため、1行ごとの `malloc` / `free` のペアが消え、返す行の確保だけが残ります。

ここで「前へ詰める」実装を選ぶと、**`BUFFER_SIZE` が大きいときに致命的に遅くなります**。読み取り単位が大きいと最初の `read` でファイル全体がバッファに載るため、1行返すたびに残り全部（最大でファイルサイズ）をコピーすることになり、行数 `M` × 残りバイト数 `N` で `O(N·M)` に膨らみます。実測では 20万行 2.3MB のファイルを `BUFFER_SIZE=10000000` で読むと **234 秒以上**かかりました（`off` 方式では 0.19 秒）。

| 20万行 / 2.3MB | 前詰め方式 | `off` 方式（本実装） |
| --- | --- | --- |
| `BUFFER_SIZE=1` | 0.90 秒 | 0.88 秒 |
| `BUFFER_SIZE=42` | 0.24 秒 | 0.22 秒 |
| `BUFFER_SIZE=9999` | 1.25 秒 | 0.19 秒 |
| `BUFFER_SIZE=10000000` | **234 秒以上** | **0.19 秒** |

`off` がずれたまま追記が必要になったときだけ `compact()` が有効データを先頭へ寄せます。これは `read()` 1回につき高々1度、しかも寄せる量はそのときの持ち越し分だけなので、全体としては入力サイズに比例するコストに収まります。

#### メモリ管理は `NULL` 経路に集約する

`NULL` を返す経路をすべて `reset_save()` に集約しました。`read()` がエラーを返したとき、`malloc()` が失敗したとき、EOF に到達したときのいずれでも、必ず持ち越しバッファを解放してから `NULL` を返します。`static` に確保済みメモリが取り残されることはありません。

#### 区切り文字の知識を1か所に閉じ込める

区切り文字と比較しているのは `nl_pos()` の1行だけです。`str_line()` は `nl_pos()` の戻り値から長さを計算し、`fill_save()` は `nl_pos()` に判断を委ね、`grow()` / `append()` / `consume()` はバイトの中身を一切見ません。そのため区切り文字を変えても影響範囲が1か所に収まり、`LINE_DELIMITER` マクロ1つでコンパイル時に差し替えられます。

#### 状態は `static` 1つだけ

読み込み状態を構造体1つの `static` にまとめているため、subject の「グローバル変数禁止」を満たし、bonus part の「`static` 変数は1つだけ」という条件も同時に満たしています。

### エッジケース

| 入力・状況 | 戻り値 |
| --- | --- |
| 空ファイル | `NULL` |
| `\n` で終わらない最終行 | `\n` を付けずにその行を返す |
| 内容が `"\n"` だけ | `"\n"` |
| 連続する空行 `"\n\n\n"` | `"\n"` を3回返してから `NULL` |
| 行長 > `BUFFER_SIZE` | 行全体を1回で返す（内部で複数回 `read()`） |
| EOF 到達後にもう一度呼ぶ | `NULL` |
| `read()` がエラー（`-1`）を返した | 持ち越し分を解放して `NULL` |
| `fd < 0` / `BUFFER_SIZE <= 0` | `NULL` |
| 標準入力（`fd = 0`） | ファイルと同じ動作 |

### 検証

以下を手元で確認済みです。

- **Norm**: `norminette get_next_line.c get_next_line_utils.c get_next_line.h` → 3ファイルとも `OK!`
- **コンパイル**: `-Wall -Wextra -Werror` で警告ゼロ。`-D BUFFER_SIZE` の有無どちらでもコンパイル可能
- **`BUFFER_SIZE` 非依存**: `1` / `2` / `3` / `42` / `9999` / `100000` / `1000000` / `10000000` の各値で上記エッジケース全件の出力が完全に一致（リークもすべて 0）
- **大きい入力**: 20万行 2.3MB のファイルを上記すべての `BUFFER_SIZE` で読み切って 1 秒未満。100万バイトの1行を `BUFFER_SIZE=1` で読んでも 0.5 秒
- **特殊なファイルディスクリプタ**: ディレクトリ / `/dev/null` / 存在しないファイル / 書き込み専用で開いた fd / 未使用の `fd=999` / `fd=INT_MAX` のいずれも `NULL` を返し、クラッシュしない
- **`\0` を含むファイル**: 行数・内容とも正しい（長さを `len` で管理しているため）
- **外部関数**: `nm -u` で確認した未定義シンボルは `read` / `malloc` / `free` のみ
- **メモリリーク**: `leaks --atExit`（macOS）で `0 leaks for 0 total leaked bytes`
- **標準入力**: `printf 'one\ntwo\n' | ./gnl` が2行を正しく返す
- **異常系**: `fd = -1` は `NULL`。読み込み途中で `close()` された fd は `NULL` を返し、内部状態がリセットされるため、別のファイルを開き直せば先頭から正しく読み直せる
