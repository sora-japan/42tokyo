# get_next_line

## Description

`get_next_line` は、**ファイルディスクリプタから1行ずつテキストを読み取る**関数を実装するプロジェクトです。

呼び出すたびに、そのファイルディスクリプタが指すテキストを1行ずつ返します。C の標準ライブラリには `getline()` が存在しますが、本プロジェクトではそれを `read()` / `malloc()` / `free()` のみを使って自作します。目的は、**`static` 変数・動的メモリ管理・ファイル I/O** の仕組みを深く理解することにあります。

**プロトタイプ:**
```c
char	*get_next_line(int fd);
```

**仕様:**
- 呼び出すたびに、ファイルディスクリプタ `fd` から次の1行を返す
- 返す行には改行文字 `\n` が含まれる（ファイル末尾が改行で終わらない最終行を除く）
- 読み取るものが無くなった場合、またはエラーが発生した場合は `NULL` を返す
- 通常ファイルと標準入力の両方で動作する
- `BUFFER_SIZE` の値（`1`, `42`, `9999`, `10000000` など）に関わらず正しく動作する

**制約（subject より）:**
- 使用可能な外部関数は `read`, `malloc`, `free` のみ
- `libft` の使用は禁止
- `lseek()` の使用は禁止
- グローバル変数の使用は禁止

## Algorithm

行を返すには、「改行が現れるまで読み進め、余った分を次回の呼び出しのために保持する」必要があります。この**持ち越し分**を保持するのが `get_next_line()` 内の `static t_save s` です。`static` なので関数を抜けても値が保持され、次回の呼び出しで続きから処理できます。

### 状態の持ち方

持ち越し分は「`\0` 終端の文字列」ではなく、**バイト列 + 長さ + 確保済み容量**の3つ組で保持します。

```c
typedef struct s_save
{
	char	*data;	/* 持ち越しバイト列 */
	size_t	len;	/* 有効バイト数 */
	size_t	cap;	/* 確保済みバイト数 */
}	t_save;
```

この形にした理由は3つあります。

1. **長さを毎回数え直さなくてよい** — 文字列として持つと、連結のたびに先頭から `\0` を探して長さを求める必要があります。`len` を持てばその走査が不要です。
2. **`\0` を含むデータでも壊れない** — subject はバイナリファイルを未定義動作としていますが、途中に `\0` があっても行の切れ目（`\n`）を見失いません。
3. **容量 `cap` を分離できる** — 「必要なバイト数」と「確保済みのバイト数」を分けて持てるため、後述の**容量の使い回し**が可能になります。これが性能上の要になります。

`static` 変数はこの構造体1つだけで、グローバル変数は使っていません。

### 全体の流れ（`get_next_line`）

1. `fd < 0` または `BUFFER_SIZE <= 0` なら `NULL` を返す（引数の検証）。
2. `fill_save()` — 持ち越し分の中に `\n` が現れるか、EOF に達するまで `read()` を繰り返し、読んだ内容をバッファ末尾に追記する。**すでに `\n` を持ち越していれば `read()` を1回も呼ばない。**
3. 読むものが無くなった（`len == 0`）／エラーが起きた場合は `reset_save()` でバッファを解放し、`NULL` を返す。
4. `str_line()` — バッファ先頭から最初の `\n` までを `\0` 終端でコピーし、返す行を作る。`\n` が無ければ末尾まで（＝最終行）。
5. `consume()` — 返した分だけバッファ内を前へ詰め、`len` を減らす。**ここでは `malloc` も `free` もしない。**
6. 切り出した行を返す。

### 各補助関数

| 関数 | 役割 |
| --- | --- |
| `grow(s, need)` | `need` バイト入るまで容量を**2倍ずつ**拡張する。容量が足りていれば何もしない（`malloc` しない）。初期容量は `BUFFER_SIZE + 1`。 |
| `append(s, buf, n)` | `grow()` で容量を確保してから、読み込んだ `n` バイトをバッファ末尾にコピーし `len` を進める。 |
| `fill_save(fd, s)` | 開始時点で `\n` があれば即座に成功を返す。無ければ `BUFFER_SIZE` 分ずつ `read()` → `append()` を繰り返し、`\n` が見つかるか `read()` が `0` を返した時点で抜ける。`read()` が `-1` を返したら失敗を返す。 |
| `nl_pos(s, from)` | `from` 以降で最初の `\n` の位置を返す（無ければ `-1`）。**新しく読んだ範囲だけ**を渡して呼ぶ。 |
| `str_line(s, &len)` | 先頭から最初の `\n`（を含む）までを `\0` 終端でコピーして返す。切り出した長さを `len` に書き戻す。 |
| `consume(s, len)` | 先頭 `len` バイトを捨て、残りをバッファ先頭へ詰める。 |
| `reset_save(s)` | バッファを解放し、`data`/`len`/`cap` をゼロに戻す。 |

### なぜこの設計か（justification）

**1行ぶんだけ読む**

`fill_save()` は `\n` を見つけた時点で読み込みを止めるため、ファイル全体を一度に読み込むことはしません。さらに、前回の呼び出しで持ち越したデータの中にすでに `\n` があれば `read()` を1回も呼びません。これは subject が明示する「新しい行を見つけたらその行を返せ／ファイル全体を読んでから処理するな」という要件を満たします。

**`BUFFER_SIZE` 非依存**

読み込み単位（`BUFFER_SIZE`）と行長を完全に分離し、追記ロジック（`grow` + `append`）が差を吸収するため、`BUFFER_SIZE` が `1` でも `10000000` でも同じ結果になります。

**容量を2倍ずつ広げる（償却計算量）**

「読むたびに `save` 全体を新しく `malloc` してコピーし直す」素朴な実装だと、長さ `N` の行を `BUFFER_SIZE` ずつ読む間に `N / BUFFER_SIZE` 回の `malloc` と、合計 `O(N² / BUFFER_SIZE)` バイトのコピーが発生します。行が長く `BUFFER_SIZE` が小さいほど爆発的に遅くなります。

そこで `cap` を持ち、**足りないときだけ容量を2倍にする**方式にしました。拡張は `log₂` 回しか起きず、コピーの総量は等比級数で抑えられて `O(N)` に収まります。

| 20000バイトの1行を読む場合 | `malloc` 回数 |
| --- | --- |
| 毎回連結し直す方式（`BUFFER_SIZE=10`） | 約 2000 回 |
| 本実装（`BUFFER_SIZE=10`） | 15 回 |
| 本実装（`BUFFER_SIZE=1`） | 18 回 |

**持ち越しは確保せずに前詰めする**

行を返したあとの残りは、新しくメモリを確保し直すのではなく、すでに確保済みのバッファ内で前へ詰めるだけにしました（`consume()`）。次の行を読むときも同じバッファをそのまま使い回せるため、1行ごとの `malloc` / `free` が消え、返す行の確保だけが残ります。

**メモリ管理**

`NULL` を返す経路をすべて `reset_save()` に集約しました。`read()` のエラー時も、`malloc()` が失敗したときも、EOF に到達したときも、必ず持ち越しバッファを解放してから `NULL` を返します。`static` に確保済みメモリが取り残されることはありません。

**状態は `static` 1つだけ**

読み込み状態を構造体1つの `static` にまとめているため、subject の「グローバル変数禁止」を満たします。

### 主なエッジケース

| 入力 | 戻り値 |
| --- | --- |
| 空ファイル | `NULL` |
| `\n` で終わらない最終行 | `\n` を付けずにその行を返す |
| 内容が `"\n"` だけ | `"\n"` |
| EOF 到達後にもう一度呼ぶ | `NULL` |
| `read()` がエラー（`-1`）を返した | 持ち越し分を解放して `NULL` |
| `fd < 0` / `BUFFER_SIZE <= 0` | `NULL` |

> **注記:** 本実装は `static` を1つだけ持つ構成で、mandatory part を対象としています。複数 fd を並行して扱う bonus part には対応していません。
