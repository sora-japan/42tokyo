## 第I章 序文

デジタル時代においては、庭にもスマートなシステムが必要です。

ある賢い庭師はこう言いました。「花を植えたら、根の様子を見るために毎日引っこ抜くわけにはいかない。」これはコードにも当てはまります——時に最も美しい成長は、私たちがプロセスを信頼し、プログラムを自然に、層を重ねながら育てていく時に起こるのです。

活気あるコミュニティガーデンの背後には、関係性のネットワークがあります。植物は孤立して育つのではなく、それぞれの種が共通のニーズを共有しながら独自の貢献をするコミュニティを形成します。ある植物は他の植物を害虫から守り、ある植物は土壌に窒素を固定し、また別の植物はデリケートな苗に日陰を提供します。この相互支援の網目構造は、優れて設計されたソフトウェアシステムがどのように機能するかを映し出しています——それぞれ異なる役割を持つ個々のコンポーネントが、調和して連携するのです。

熟練した庭師が健全な土壌が健全な植物を生むことを知っているように、経験豊富なプログラマーは、よく構造化されたコードが堅牢なアプリケーションへと成長することを理解しています。コードを整理することは庭を計画することに似ていると気づくでしょう。ある要素は保護が必要であり、ある要素は成長する余地が必要であり、最良のシステムは、すべてのものに適切な場所と目的があるときに生まれます。

このプロジェクトでは、コミュニティガーデンの発展に本当に役立ちうるツールを構築しながら、プログラミングスキルを育てていきます。あなたが書くすべての1行のコードは、可能性というデジタルな土壌に植えられた種なのです。

## 第II章 AIの利用について

### コンテキスト

学習の過程で、AIはさまざまなタスクを支援することができます。AIツールの多様な能力と、それがどのように作業を支援できるかを探る時間を取りましょう。しかし、常に注意深く、結果を批判的に評価してください。コードであれ、ドキュメントであれ、アイデアであれ、技術的な説明であれ、あなたの質問が適切に構成されていたか、生成された内容が正確であるかを完全に確信することはできません。仲間はミスや見落としを避けるための貴重なリソースです。

### 主なメッセージ

- 反復的で退屈なタスクを減らすためにAIを使いましょう。
- コーディングと非コーディングの両方において、将来のキャリアに役立つプロンプトスキルを磨きましょう。
- AIシステムがどのように機能するかを学び、一般的なリスク・バイアス・倫理的問題をよりよく予測し回避できるようにしましょう。
- 仲間と協力することで、技術的スキルと対人スキルの両方を伸ばし続けましょう。
- 完全に理解し、責任を持てるAI生成コンテンツのみを使用しましょう。

### 学習者としてのルール

- AIツールを探求し、その仕組みを理解する時間を取りましょう。それによって倫理的に使用し、バイアスを減らすことができます。
- プロンプトを書く前に、問題についてよく考えましょう——これにより、より明確で、詳細で、適切な語彙を使った関連性の高いプロンプトを書けるようになります。
- AIが生成したものを体系的にチェック・レビュー・疑問視・テストする習慣を身につけましょう。
- 常にピアレビューを求めましょう——自分自身の検証だけに頼らないでください。

### フェーズの成果

- 汎用および領域特化型のプロンプトスキルの両方を伸ばす。
- AIツールを効果的に活用して生産性を高める。
- 計算論的思考、問題解決力、適応力、協調性を強化し続ける。

### コメントと例

- 試験、評価など、本当の理解を示さなければならない状況に定期的に直面するでしょう。準備をし、技術力と対人スキルの両方を伸ばし続けてください。
- 自分の推論を説明し、仲間と議論することは、しばしば理解のギャップを明らかにします。ピアラーニングを優先しましょう。
- AIツールはしばしばあなた固有のコンテキストを欠いており、汎用的な回答になりがちです。あなたと同じ環境を共有する仲間は、より関連性が高く正確な洞察を提供できます。
- AIが最も可能性の高い答えを生成する傾向がある一方で、仲間は代替の視点や貴重なニュアンスを提供できます。彼らを品質チェックポイントとして活用しましょう。

**✓ 良い実践例:**
AIに「ソート関数をどうテストすればいいですか？」と尋ねる。いくつかのアイデアが得られる。それらを試し、仲間とレビューする。一緒にアプローチを洗練させる。

**✗ 悪い実践例:**
AIに関数全体を書かせて、プロジェクトにそのままコピー＆ペーストする。ピア評価の際、それが何をするのか、なぜそうなっているのか説明できない。信用を失い——プロジェクトを不合格になる。

**✓ 良い実践例:**
AIを使ってパーサーの設計を手伝ってもらう。その後、仲間とロジックを一緒に確認する。2つのバグを見つけて一緒に書き直す——より良く、よりクリーンに、そして完全に理解した状態で。

**✗ 悪い実践例:**
プロジェクトの重要な部分のコードをCopilotに生成させる。コンパイルは通るが、パイプの処理方法を説明できない。評価の際に正当化できず、プロジェクトを不合格になる。

## 第V章 演習0: 最初の種を植える

| 項目 | 内容 |
|---|---|
| ファイル名 | ft_garden_intro |
| ディレクトリ | ex0/ |
| 提出ファイル | ft_garden_intro.py |
| 許可された関数 | print() |

複雑なガーデン管理システムを構築する前に、Pythonプログラムがどのように動作するかを理解する必要があります。
すべてのPythonプログラムには開始点——実行が始まる場所——が必要です。それはまさに、庭に最初の種を植えるようなものです！

課題は、庭にある植物の情報を表示する、あなたにとって初めてのPythonプログラムを作成することです。

**要件:**

- `python3 ft_garden_intro.py` で直接実行した際に動作するプログラムを作成すること
- 特別な `if __name__ == "__main__":` パターンを使用すること
- 以下の植物情報を単純な変数に保存すること：名前、高さ、年齢
- `print()` を使って植物情報を表示すること
- 以下の出力例を模倣すること（評価時に厳密な出力チェックは行われません）

**出力例:**
```
$> python3 ft_garden_intro.py
=== Welcome to My Garden ===
Plant: Rose
Height: 25cm
Age: 30 days

=== End of Program ===
```

> プログラムがどのように開始・実行されるかを理解することは、クラスなどのより複雑なオブジェクト指向の機能に進む前の基礎となります。

**注:** この演習以降、このモジュール内（および今後のPythonプロジェクト）で、テスト用に `if __name__ == "__main__":` ブロックを使用することが許可されています。このパターンは各演習の許可された関数には明示的に表示されませんが、プロジェクト全体を通して利用可能です。

> `if __name__ == "__main__":` の行がなぜ重要なのかを説明できる必要があります。これはインポートの概念につながり、今後のプロジェクトの一部となります。しかし、この良い習慣を今のうちから導入しておくことが重要です。

> `#!` で始まる特別な行から始まるPythonファイルに気づいたことはありますか？この「シバン（shebang）」行が何をするのか、なぜスクリプトを直接実行可能にするのに役立つのかを調べてみましょう。評価では、この「シバン」を使うようにスクリプトをその場で更新するよう求められます。

## 第VI章 演習1: ガーデンデータ整理システム

| 項目 | 内容 |
|---|---|
| ファイル名 | ft_garden_data |
| ディレクトリ | ex1/ |
| 提出ファイル | ft_garden_data.py |
| 許可された関数 | print() |

コミュニティガーデンでは、複数の植物とその情報を追跡する必要があります。複数の植物のデータを効率的に保存・表示する必要があります。

各植物は以下を持ちます:

- 名前
- 高さ（センチメートル）
- 年齢（日数）

少なくとも3種類の異なる植物のデータを管理し、その情報を整理された形で表示するプログラムを作成してください。

**必須要件:** 個々の植物を個別に扱うのではなく、任意の植物のモデルとして機能する `Plant` **クラス**を作成する必要があります。すべての植物は同じ**属性**（特性）——名前、高さ、年齢——を使って記述されます。各植物ごとに、クラスが**インスタンス化**され、その後属性が特定の値に設定されます。各属性には好きな名前を使用できます。

植物情報を表示するための `show()` **メソッド**をクラス内に作成してください。

**出力例:**
```
$> python3 ft_garden_data.py
=== Garden Plant Registry ===
Rose: 25cm, 30 days old
Sunflower: 80cm, 45 days old
Cactus: 15cm, 120 days old
```

> 現在、植物情報をどのように保存していますか？これを行う方法は複数あります。植物が増えるとどんな課題が生じるでしょうか？次の演習では、あなたのアプローチを進化させる必要が出てくるかもしれません。

> すでにPythonプログラミングやオブジェクト指向プログラミングの経験がある場合、おそらく最初から高度な解決策に進むでしょう。その場合、次の演習は少し冗長に感じるかもしれません。

## 第VII章 演習2: 植物成長シミュレーター

|---|---|

ガーデンマネージャーは時間経過による植物の成長をシミュレートしたいと考えています。植物がどのように変化するかを追跡し、その状態を変更するための**操作**を提供する必要があります。

**要件:**

## 第IX章 演習4: ガーデンセキュリティシステム

| 項目 | 内容 |
|---|---|
| ファイル名 | ft_garden_security |
| ディレクトリ | ex4/ |
| 提出ファイル | ft_garden_security.py |
| 許可された関数 | print(), range(), round() |

ガーデンマネージャーはデータの整合性を懸念しています。一部のボランティアが誤って無効な値（負の高さ、あり得ない年齢）を設定し、植物データを破損させてしまいました。機密データを**保護**し、**カプセル化**する安全なシステムを作成する必要があります。

**要件:**

- データの破損から保護するために `Plant` クラスを改良すること
- 植物データを変更するための制御された方法を提供すること：`set_height()`、`set_age()`
- 植物データに安全にアクセスする方法を提供すること：`get_height()`、`get_age()`
- 植物の高さが負の値にならないよう、バリデーションを通じて保証すること
- 植物の年齢が負の値にならないよう、バリデーションを通じて保証すること
- 無効な値が渡された場合、クラスからエラーメッセージを表示し、データを変更しない、または植物をデフォルト値で作成すること
- **カプセル化**を使用すること：クラスの属性が直接使用されるのを防ぐために「プロテクテッド」規約（**マングリング**ではなく）を使用すること

データを保存する前に**検証（validate）**するシステムをどう作るか、データの整合性を確保する方法を考えてみましょう。

**出力例:**
```
$> python3 ft_garden_security.py
=== Garden Security System ===
Plant created: Rose: 15.0cm, 10 days old

Height updated: 25cm
Age updated: 30 days

Rose: Error, height can't be negative
Height update rejected
Rose: Error, age can't be negative
Age update rejected

Current state: Rose: 25.0cm, 30 days old
```

## 第X章 演習5: 特殊な植物タイプ

| 項目 | 内容 |
|---|---|
| ファイル名 | ft_plant_types |
| ディレクトリ | ex5/ |
| 提出ファイル | ft_plant_types.py |
| 許可された関数 | super(), print(), range(), round() |

庭では今、花・木・野菜という異なるタイプの植物を扱う必要があります。それぞれのタイプは固有の特性を持ちますが、**親**カテゴリから共通の植物特性を**継承**します。

**要件:**

- 共通の特性（名前、高さ、年齢）を保持する、前の演習の `Plant` クラスから始めること
- 特殊なタイプ：`Flower`（花）、`Tree`（木）、`Vegetable`（野菜）を作成すること
- 各特殊タイプは基本的な植物の特性を**継承**すること
- `Flower` に必要なもの：`color`（色）属性と `bloom()`（咲く）能力
- `Tree` に必要なもの：`trunk_diameter`（幹の直径）属性と `produce_shade()`（日陰を作る）能力
- `Vegetable` に必要なもの：`harvest_season`（収穫期）と `nutritional_value`（栄養価）の属性
- 特殊な植物を作成する際は、新しいクラスの中から `super()` を使って親のメソッドを呼び出すこと。これは `__init__()` を含む任意のメソッドに適用できます
- 特殊クラスに対する `show()` の呼び出しは、標準の `Plant` の出力と、特殊な植物の追加特性を表示する必要があります。メソッドの**オーバーライド**は親に既に存在するコードを再利用できます
- 各植物タイプのインスタンスを少なくとも1つ作成すること。花を咲かせること。栄養価は0から始まり、野菜の `age()` と `grow()` メソッドが呼び出されるたびに増加するようにすること

- 異なる特殊タイプ間で共通の植物コードを重複させないこと
- 3つの新しいクラスにおいて、新しい属性を検証（バリデート）する必要はない
